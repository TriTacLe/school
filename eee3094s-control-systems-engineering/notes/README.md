# EEE3094S notes index

The deck is the unit. `decks/` holds one file per Amathuba deck and is the only copy of the content. Everything else embeds those files, so a fact lives in exactly one place and there is nothing to keep in sync.

- `decks/N.N Title.md` - full mirror of one deck, stamped with its Amathuba path and its local PDF
- `Module N/Week NN - ...md` - the calendar view. Dates, admin, what to pre-watch, to do, then the week's decks embedded, then a recall check and a capture block. This is what you open in a lecture
- `01 Intro revision.md` and friends - the topic view. Same decks, embedded in concept order for revision

Folder and file names follow Amathuba's own module and chapter titles, so a page on Amathuba maps straight to a file here.

Because the decks are embedded rather than copied, you read one file in a lecture and see everything inline. Write what the lecturer adds under `## Lecture capture` at the bottom of the week file, so your own words never get mixed into the deck mirror.
