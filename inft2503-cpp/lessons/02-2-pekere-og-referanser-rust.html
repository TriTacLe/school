Pekere og referanser i Rust

Forberedelser

Om du bruker juCi++ kan du lage et nytt Rust prosjekt ved å velge File, Create Project, Rust i menyen. Da vil du også få spørsmål om å installere både Rust og rust-analyzer om du ikke allerede har installert disse programmene. Rust-analyzer er et program, nærmere bestemt en language server, som gir utvidet IDE støtte for Rust. Merk at noen feil og advarsler blir kun vist når du lagrer Rust filene. Dette er noe som vil bli forbedret i rust-analyzer i fremtiden.

Introduksjon

Rust har blitt det tredje systemprogrammeringsspråket i tillegg til C og C++, som vi kan benytte når vi trenger å lage ressurseffektive programmer eller programvarebiblioteker. I forhold til C og C++, som har blitt brukt i flere tiår, er Rust svært nytt. Versjon 1.0 av Rust ble utgitt i 2015, men har blitt relativt populært som systemprogrammeringsspråk i noen miljøer, spesielt der det er ekstra fokus på sikkerhet.

Ulempen med C og C++ er at det er svært lett for nye programmerere å gjøre feil. Det blir tilgjengelig bedre og bedre analyseverktøy for å finne feil i C og C++ kildekode, men disse programmeringsspråkene er ikke designet spesielt for dette, og det finnes feil som er svært vanskelig å oppdage automatisk. Rust er et forsøk på å forbedre denne situasjonen, og er laget for at det skal være lettere å oppdage feil i kildekoden samtidig som at ressursbruken i Rust programmer skal være bortimot lik programvaren skrevet i C og C++.

Før vi ser på Rust kode, skal vi se på pekere og referanser i C og C++. I C har vi pekere, og C++ utvidet dette konseptet med referanser. En C peker trenger ikke å peke til noe, men en C++ referanse er alltidt knyttet til en variabel. Vi kan bruke både pekere (ptr) og referanser (ref) i C++:

#include <iostream>

using namespace std;

int main() {
  int value;                     // Depending on compiler implementation, a random value is possibly stored at some memory address,
                                 // and 4 bytes are typically needed to store an int value
  value = 2;                     // The value 2 is stored at the same memory address
  cout << &value << endl;        // Outputs the start of the memory address where the value 2 is stored
  cout << sizeof(value) << endl; // Outputs how many bytes are needed to store an int value at the current system

  int *ptr;              // Depending on compiler implementation, might point to a random memory address
  cout << *ptr << endl;  // Outputs the int value stored at possibly a random memory address. Might cause segmentation fault.
  ptr = nullptr;         // Pointer now points to the memory address 0. This indicates that ptr does not point to a valid address.
  ptr = &value;          // Pointer now points to memory address of the value 2
  cout << value << endl; // Outputs the value 2
  *ptr = 4;              // Change value at address ptr to 4.
  cout << *ptr << endl;  // Outputs 4
  cout << value << endl; // Outputs 4

  // int &ref;         // Does not compile, a reference must refer to a value
  int &ref = value;    // ref is now reference to value, and can be used as the value variable can be used.
  cout << ref << endl; // Outputs 4
  ref = 6;
  cout << ref << endl;   // Outputs 6
  cout << value << endl; // Outputs 6
}

Pekere i Rust

Det anbefales ikke å jobbe med rene pekere i Rust, men om en må bruke de kreves det at en legger noe av koden i unsafe-blokker:

fn main() {
    let mut value = 2; // Create a 32-bit (4 byte) integer (i32 type in Rust)
                       // The mut (mutable) keyword makes value alterable (non-const)
                       // In C and C++ variables are non-const (mut) by default, while in Rust the variables are const.
    let ptr: *mut i32 = &mut value;
    unsafe {
        *ptr = 4; // Changes value to 4. This statement must be in an unsafe block
        println!("{}", *ptr); // Output 4. This statement must be in an unsafe block.
    }
    println!("{}", value); // Output 4
}

Det er svært få tilfeller at en behøver å bruke unsafe-blokker i Rust, og det er derfor et mål å prøve å unngå disse. Dette oppnås blant annet ved å bruke refereranser i stedet.

Referanser i Rust

Syntaksen for referanser i Rust er svært lik pekersyntaksen:

fn main() {
    let mut value = 2;
    let value_ref: &mut i32 = &mut value; // Note that &mut i32 (reference) is used instead of *mut i32 (pointer)
                                          // : &mut i32 is not needed
    *value_ref = 4; // Changes value to 4
    println!("{}", *value_ref); // Output 4. Could also write println!("{}", value_ref); here.
    println!("{}", value); // Output 4
}

Derimot er bruken av referanser mye strengere i Rust enn i C++, og dette er grunnen til at det er tryggere å jobbe med for eksempel referanser i Rust enn i C++. Det første eksempelet er likt det forrige, men rekkefølgen på println!-kallene er endret:

fn main() {
    let mut value = 2;
    let value_ref = &mut value;
    *value_ref = 4;
    println!("{}", value); // Compile error since value_ref is reffering to value and will be used after this statement.
    println!("{}", *value_ref);
}

I Rust er det altså ikke lov å bruke en verdi hvis det fortsatt er en referanse som refererer til denne verdien, og denne referansen vil bli brukt senere. Om du prøver å kompilere koden over selv vil du se følgende feilmelding: "cannot borrow value as immutable because it is also borrowed as mutable". Denne feilmeldingen er vanskelig å forstå i starten, men vi skal se nærmere på hva dette betyr.

Selv om en jobber med referanser i Rust, har Rust lagt til et ekstra hjelpesystem for å gjøre det tryggere å jobbe med referanser i Rust. Det er dette hjelpesystemet som bruker konseptet borrow (lån).

Først skal vi se på et eksempel i C++ der referanser blir brukt på feilaktig måte som kan føre til programvarefeil:

#include <iostream>
#include <vector>

using namespace std;

int main() {
  vector<int> vec = {1, 2, 3}; // Create dynamic array
  for (auto e : vec)
    cout << e << endl; // Outputs 1\n2\n3\n

  auto &ref = vec[0];
  cout << ref << endl; // Outputs 1

  vec.clear(); // Erase all elements in vec

  cout << ref << endl; // Depending on compiler implementation, might cause segmentation fault

  for (auto e : vec)
    cout << e << endl; // No output
}

Hvis vi prøver å gjøre det samme i Rust vil vi få feilmelding ved kompilering:

fn main() {
    let mut vec = vec![1, 2, 3]; // Create dynamic array
    println!("{:?}", vec); // Outputs [1, 2, 3]

    let element_ref = &mut vec[0]; // Reference to first element in vec
    println!("{}", element_ref); // Outputs 1

    vec.clear(); // Erase all elements in vec

    println!("{}", element_ref); // Compilation error: cannot borrow `vec` as mutable more than once at a time

    println!("{:?}", vec); // Outputs []
}

Igjen er feilmeldingen litt vanskelig å forstå, men borrow-systemet tillater ikke at element_ref blir brukt etter at vec blir brukt i vec.clear(). Merk at dette gjelder uansett hva vec blir brukt til. For eksempel om vi erstatter vec.clear() med println!("{:?}", vec); så ville vi fått liknende feilmelding selv om denne operasjonen er trygg. Du mister litt frihet i Rust, men dette fører igjen til at det er litt tryggere å kode i Rust enn i C og C++.
