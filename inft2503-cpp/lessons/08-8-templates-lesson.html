Leksjon 8: Templates

Vi skal i denne leksjonen se på en spesiell teknikk (template) som gjør at vi kan lage kode som er anvendelig til mange forskjellige formål. Standard Template Library (STL) har brukt denne teknikken til å lage et klassebibliotek med mange nyttige klasser. Poenget med template er at du kan lage klasser og/eller funksjoner som fungerer uavhengig av hvilke(n) datatype(r) de skal jobbe med. Vi lager en generell algoritme eller klasse, og kan seinere anvende den på de dataene vi måtte ønske.

Skrevet av Mildrid Ljosland, Else Lervik, Tore Berg Hansen og Ole Christian Eidheim.

Funksjonstemplate

Vi starter med å se på et eksempel der vi lager en funksjon som template.

Vi ønsker å sortere en tabell. Algoritmen for sortering er den samme uansett om det er heltall, desimaltall, navn eller hva som helst annet som skal sorteres. Det eneste kravet vi må stille, er at dataene har innbyrdes rekkefølge, slik at det er mulig å avgjøre om et element er større, lik eller mindre enn et annet element.

Vi bruker følgende sorteringsalgoritme:

Først finner vi minste element og plasserer det først, deretter finner vi nest minste og plasserer det som nummer to, osv. til vi har plassert alle elementene.

Her er koden:

//
// sort() fra sort.cpp
//

template <typename Type>
void sort(Type &data) {
  for (size_t i = 0; i < data.size(); ++i) {
    int smallest = i;
    for (size_t j = i + 1; j < data.size(); ++j) {
      if (data[j] < data[smallest])
        smallest = j;
    }
    auto help = data[i];
    data[i] = data[smallest];
    data[smallest] = help;
  }
}

Type er betegnelsen for template-typen, det vi kaller den generiske typen. template <typename Type> forteller kompilatoren at vi har en template, og at vi ønsker å kalle den generiske typen for Type. Vi kunne ha brukt et hvilket som helst syntaktisk lovlig navn, i litteraturen brukes ofte navnet T for den generiske typen. Av historiske årsaker kan vi i stedet for typename også skrive class, men typename er mest vanlig å bruke i nyere kode.

Anta nå at vi ønsker å sortere en tabell av desimaltall. Da tar vi i bruk (instansierer) templaten.

//
// main() fra sort.cpp
//
int main() {
  std::default_random_engine generator;
  std::uniform_real_distribution<double> distribution(0.0, 10.0);

  vector<double> table;
  for (size_t i = 0; i < 10; ++i)
    table.emplace_back(distribution(generator));

  sort(table);

  for (auto &e : table)
    cout << e << endl;
}

8.09567

Funksjonen sort() kalles på samme måte som en helt vanlig funksjon. Kompilatoren finner selv ut at det er en template-funksjon, og at table er vector<double>, slik at Type skal erstattes med vector<double> i dette tilfellet.

Ved instansieringen lager kompilatoren en “ekte” funksjon ved å erstatte den generiske typen med den typen vi bruker i funksjonskallet. Kjør eksemplet.

Vi kan også lage en template for å søke i en tabell:

//
// search() fra search.cpp
//
template <typename Type>
size_t search(const vector<Type> &table, Type search_element) {
  size_t pos = 0;
  while (pos < table.size() && table[pos] != search_element)
    ++pos;
  if (pos < table.size())
    return pos;
  else
    return -1;
}

Her bruker vi den generiske typen to ganger i argumentlista, og må derfor passe på å bruke samme type til begge de aktuelle argumentene i funksjonskallet:

vector<double> table;
auto pos = search(table, 0.5);

Skriver vi i stedet

vector<double> table;
auto pos = search(table, 1); // feil, fordi 1 er av typen int

får vi kompileringsfeil fordi double og int er forskjellige typer.

Men denne setningen fungerer:

vector<double> table;
auto pos = search(table, static_cast<double>(1));

Bruk helst static_cast/dynamic_cast i stedet for C-style cast som for eksempel: (double)1. Fordelen med static_cast og dynamic_cast er at de gir feilmeldinger ved kompilering. static_cast er den enkleste som er mest vanlig å bruke, mens dynamic_cast brukes ved polymorfi som vi har sett eksempler på tidligere.

Det er imidlertid ingenting i veien for å bruke to eller flere generiske typer i en template. Da lister vi dem opp med komma mellom:

//
// print.cpp
//
#include <iostream>

using namespace std;

template <typename Type1, typename Type2>
void print(const Type1 &first, const Type2 &second) {
  cout << first << " " << second << endl;
}

int main() {
  int number = 5;
  print("Svaret er ", number);
  print(100, 0.05);
  print('\n', "Hallo");
}

/* Kjøring av programmet:

Svaret er  5
100 0.05

 Hallo
*/

Pass på at du oppgir alle de generiske typene i argumentlista til funksjonen. Gjør du ikke det, kan ikke kompilatoren vite hvilken du ønsker å bruke, og gir derfor kompileringsfeil. Trenger du en egen type til returverdien eller til en intern variabel, må du lage et ekstra argument av denne typen, og sette inn en eller annen verdi (likegyldig hvilken verdi, men riktig type) når du kaller funksjonen.

Template er en måte å lage polymorfe funksjoner på, dvs. funksjoner som oppfører seg forskjellig avhengig av hvordan de brukes. Arvede (virtuelle) funksjoner og overloadede funksjoner er andre eksempler på polymorfe funksjoner.

I arvede funksjoner må argumenttypene være de samme fra funksjonskall til funksjonskall, mens innholdet (algoritmen) kan være forskjellig. I template er det motsatt, algoritmen er fast, men argumenttypene kan variere. I overloadede funksjoner må argumenttypene (og/eller antall argumenter) variere fra prototyp til prototyp, men innholdet kan være likt eller forskjellig.

Template er en automatisert måte å lage overloadede funksjoner på. Vi lager en mal som kompilatoren bruker til å lage de virkelige funksjonene. Men den lager (instansierer) bare de versjonene den finner ut at den trenger.

Hvordan finner så kompilatoren ut hvilke versjoner den trenger?

Når den treffer på et funksjonskall vil den sjekke hvilke typer de aktuelle argumentene har. Deretter vil den undersøke om det finnes en prototyp som passer akkurat, dvs. slik at argumenttypene stemmer overens uten at noen av dem behøver å omformes. I så fall brukes den, og den tilhørende funksjonsdefinisjon lenkes inn. Finnes ikke en slik funksjon, prøver den template-definisjonen. Også her er det et krav at argumenttypene skal passe akkurat når de(n) generiske typen(e) erstattes med de(n) aktuelle. Finner kompilatoren fortsatt ingen funksjon som passer, går den tilbake til de “vanlige” funksjonene, og prøver å finne en som passer akseptabelt godt, dvs. som passer etter at argumenttypene er omformet etter bestemte regler (f.eks. kan int omformes til double). Finnes heller ikke en slik, gir kompilatoren opp, og genererer en feilmelding. Den gir også feilmelding hvis den på noen av de tre stadiene finner mer enn en funksjon som passer.

Dette kan vi utnytte hvis vi ønsker å ha en template-funksjon som dekker de fleste datatypene, men en spesialversjon for noen få datatyper. Da kan vi definere en (eller flere) "vanlig(e)" funksjon(er) for de(n) datatypen(e) vi ønsker spesialversjon, og en template-funskjon med samme navn for standardversjonen. Kompilatoren vil først prøve spesialversjonen, bare hvis den ikke passer, prøver den standardversjonen.

Generelt: Når du lager en template, tenk over om det er noen datatyper den ikke passer for. Angi eventuelle begrensninger i hodekommentaren, eller lag flere versjoner, slik at alle tilfeller blir dekket.

Klassetemplate

Når vi definerer en klasse som en template, kan vi definere datamedlemmer med generisk type i tillegg til at medlemsfunksjonene kan ha argumenter med generisk type. For eksempel slik:

//
// point.cpp
//
#include <iostream>

using namespace std;

template <typename Type>
class Point {
public:
  Type x, y, z;

  Point(Type x, Type y, Type z) : x(x), y(y), z(z) {}

  Point operator+(const Point &other) {
    Point point = *this;
    point.x += other.x;
    point.y += other.y;
    point.z += other.z;
    return point;
  }

  friend ostream &operator<<(ostream &os, const Point &punkt) {
    return os << "(" << punkt.x << ", " << punkt.y << ", " << punkt.z << ")";
  }
};

int main() {
  {
    Point<int> p1(1, 2, 3), p2(2, 2, 2);

    cout << (p1 + p2) << endl;
  }
  {
    Point<double> p1(1.5, 2.5, 3.5), p2(2.0, 2.0, 2.0);

    cout << (p1 + p2) << endl;
  }
}
/* Utskrift:
(3, 4, 5)
(3.5, 4.5, 5.5)
*/
