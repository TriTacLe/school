Smarte pekere og polymorfi i Rust

Introduksjon

Denne leksjonen fokuserer kun på Rust. Det er mulig å oppnå polymorfi i C, for eksempel bruker GUI biblioteket GTK dette, men polymorfi i C er komplisert og utenfor pensum for dette emnet. Interesserte kan likevel lese om dette for eksempel her: Polymorphism in C.

Smart pekere

Direkte oppretting av verdier i det frie lageret i Rust krever i utgangspunktet unsafe-blokker:

use std::alloc::{alloc, dealloc, Layout};

fn main() {
    let layout = Layout::new::<i32>(); // Type of value to be created in the heap
    unsafe {
        let ptr = alloc(layout); // Create memory range for an integer in the heap

        *ptr = 42; // Store the value 42 on the heap

        println!("{}", *ptr); // Outputs 42
        println!("{:p}", ptr); // Outputs address of the value in the heap

        dealloc(ptr, layout); // Free the memory ptr points to
    }
}

Men Rust har som i C++ også smarte pekere. Typen i Rust som er mest lik std::unique_ptr i C++ er Box, og bruken av smarte pekere krever ikke unsafe-blokker:

fn main() {
    let ptr = Box::new(42); // Store the value 42 in the heap
    println!("{}", *ptr); // Outputs 42
    println!("{:p}", ptr); // Outputs address of the value in the heap
    // The memory ptr points to is freed at end of scope
}

Polymorfi

Studer først følgende eksempel i C++:

#include <iostream>
#include <vector>

using namespace std;

class Surface {
public:
  Surface(double length_, double width_) : length(length_), width(width_) {}

  double length;
  double width;

  double area() {
    return length * width;
  }

  virtual std::string string() {
    return "length: " + to_string(length) + ", width: " + to_string(width) +
           ", area: " + to_string(area());
  }
};

class ColoredSurface : public Surface {
public:
  ColoredSurface(double length, double width, double red_, double green_, double blue_)
      : Surface(length, width), red(red_), green(green_), blue(blue_) {}

  double red;
  double green;
  double blue;

  std::string string() override {
    return Surface::string() +
           ", color: (" + to_string(red) + ", " + to_string(green) + ", " + to_string(blue) + ")";
  }
};

int main() {
  vector<std::unique_ptr<Surface>> surfaces;

  surfaces.emplace_back(new Surface(2.0, 3.0));
  surfaces.emplace_back(new ColoredSurface(2.0, 3.0, 0.0, 0.0, 1.0));

  for (auto &surface : surfaces) {
    cout << surface->width << endl;    // Outputs 3
    cout << surface->area() << endl;   // Outputs 6
    cout << surface->string() << endl; // Outputs length: 2, width: 3, area: 6, and color for ColoredSurface objects

    if (auto colored_surface = dynamic_cast<ColoredSurface *>(surface.get()))
      cout << colored_surface->blue << endl; // For ColoredSurface objects only: outputs 1
  }
}

Vi kan implementere dette eksempelet i Rust, men det krever litt ekstra kode:

use std::any::Any;

struct Surface {
    width: f64, // f64 corresponds to double in Rust
    length: f64,
}

trait GeometricQuantities {
    fn area(self: &Self) -> f64; // self is a reference to the calling Surface instance
    fn string(self: &Self) -> String;
}

impl GeometricQuantities for Surface {
    // All functions in the trait GeometricQuantities must be implemented here,
    // and only functions in GeometricQuantities can be implemented.
    fn area(self: &Self) -> f64 {
        return self.width * self.length;
    }

    fn string(&self) -> String {
        return format!(
            "length: {}, width: {}, area: {}",
            self.length,
            self.width,
            self.area()
        );
    }
}

struct ColoredSurface {
    surface: Surface, // Extend Surface struct by adding a Surface object
    red: f64,
    green: f64,
    blue: f64,
}

impl GeometricQuantities for ColoredSurface {
    // All functions in the trait GeometricQuantities must be implemented here,
    // and only functions in GeometricQuantities can be implemented.
    fn area(self: &Self) -> f64 {
        return self.surface.area();
    }

    fn string(&self) -> String {
        return format!(
            "{}, color: ({}, {}, {})",
            self.surface.string(),
            self.red,
            self.green,
            self.blue
        );
    }
}

fn main() {
    let mut surfaces = Vec::<Box<dyn Any>>::new();

    surfaces.push(Box::new(Surface {
        width: 2.0,
        length: 3.0,
    }));

    surfaces.push(Box::new(ColoredSurface {
        surface: Surface {
            width: 2.0,
            length: 3.0,
        },
        red: 0.0,
        green: 0.0,
        blue: 1.0,
    }));

    for surface in &surfaces {
        // If surface is of type Surface:
        if let Some(surface) = surface.downcast_ref::<Surface>() {
            println!("{}", surface.width); // Outputs 2
            println!("{}", surface.area()); // Outputs 6
            println!("{}", surface.string()); // Outputs length: 2, width: 3, area: 6
        }
        // If surface is of type ColoredSurface:
        else if let Some(colored_surface) = surface.downcast_ref::<ColoredSurface>() {
            println!("{}", colored_surface.surface.width); // Outputs 2
            println!("{}", colored_surface.area()); // Outputs 6
            println!("{}", colored_surface.string()); // Outputs length: 2, width: 3, area: 6, color: (0, 0, 1)

            println!("{}", colored_surface.blue); // Outputs 1
        }
    }
}

For å lagre flere forskjellige overflatetyper i en Vec må vi lagre overflatene som Box pekere. Dette likner slik vi gjør det i C++ med unique_ptr. Derimot må typen til Box være en Any trait for å kunne utføre dynamisk cast. Da må vi utføre casting for både Surface og ColoredSurface objekter.

Rust har noen mangler når det kommer til objektorientert programmering, men det samme har Java i forhold til C++, for eksempel multiple inheritance. Det finnes som regel måter å oppnå ønsket funksjonalitet, selv om det kan være litt mer tungvindt. I Rust er det vanligst å prøve å unngå å bruke arv og polymorfi, og heller se etter alternative løsninger.
